Module 1 · Foundations

Arrays & Linked Lists

Understand memory layout, indexing and insertion trade-offs.

Arrays: direct access

An array stores elements in a sequence of adjacent memory locations. With an index, the address can be calculated directly, so reading an element by index is typically O(1).

A[0]A[1]A[2]A[3]
Adjacent storage → direct indexing
Analogy: Think of numbered lockers. If you know locker 17, you know where to look. Adding a locker in the middle can require shifting later lockers.

Linked lists: connected nodes

A singly linked list stores a value and a link to the next node. It can make insertion or deletion near a known position efficient, but reaching an arbitrary position requires traversal.

10 | next→20 | next→30 | null
OperationArrayLinked list
Index accessO(1)O(n)
Insert frontOften O(n)O(1) with head
Unsorted searchO(n)O(n)

Misconception

“Linked lists are always faster for insertion.” The insertion itself may be O(1), but finding the insertion point can cost O(n). Arrays may also be faster in practice because contiguous memory is cache-friendly.

Mini exercise: You repeatedly need the 10,000th element. Which structure is a natural first choice?
Key takeaway
Choose based on the operations you perform most often.

Module 2 · Linear Tools

Stacks, Queues & Hashing

Recognize LIFO, FIFO and key-based lookup patterns.

Stack — LIFO

A stack removes the newest item first. Core operations include push and pop. Common applications include undo systems, expression parsing, recursion and depth-first search.

CBA← pop

Queue — FIFO

A queue removes the oldest waiting item first. It is useful for print jobs, request handling and breadth-first search.

Analogy: Stack = pile of plates. Queue = people waiting in a line.

Hash table

A hash table uses a hash function to map a key toward a bucket or index. Under typical assumptions, lookup, insertion and deletion are expected to be O(1), but collisions and resizing affect performance.

user42→ hash →bucket→profile

Misconception

“Hash tables are always O(1).” Average or expected performance can be O(1) with suitable assumptions; collisions, poor hashing and adversarial inputs can change the behavior.

Pattern detector
“Most recent” → stack. “First come” → queue. “Given this key, find its value” → hash table.

Trees, BSTs & Heaps

Learn hierarchy, ordered search and priority-based access.

Trees

Trees represent parent-child relationships. They are useful for file systems, organizational hierarchies and syntax trees.

Binary Search Tree

A BST maintains an ordering rule: smaller keys are placed to the left and larger keys to the right (with a chosen duplicate policy). A balanced BST can support search near O(log n), while a skewed tree can degrade toward O(n).

Traversals

Preorder: root → left → right. Inorder: left → root → right. Postorder: left → right → root. Inorder traversal of a valid BST visits keys in sorted order.

Heap / Priority Queue

A heap focuses on priority. In a min-heap the smallest element is at the root; in a max-heap the largest is. A heap is commonly used to implement priority queues.

Analogy: A heap is like a triage desk: the highest-priority case is quickly available, but the entire waiting area is not fully sorted.

Misconception

Not every tree is a BST. A BST is a specialized binary tree with an ordering rule.

Remember
BST = ordered search. Heap = priority access. General tree = hierarchy.

Module 4 · Integration

Choose the Right Data Structure

Turn requirements into structure choices instead of memorizing definitions.

A practical decision framework

Fast index?→ArrayFast key lookup?→Hash table

LIFO?→StackFIFO?→QueuePriority?→Heap

Real-world scenarios

Browser back: stack, because the most recent page is the first one you return from.

User ID → profile: hash table/map, because the dominant operation is lookup by a key.

Emergency scheduler: priority queue, commonly backed by a heap, because the next item depends on priority.

File system: tree, because folders and files naturally form a hierarchy. DFS or BFS can then be layered on top using a stack or queue.

Mastery rule: Identify the dominant operation, ordering requirement and constraints. Then choose the structure whose strengths fit the workload. Finally consider memory, implementation complexity and worst-case behavior.

Cheat Sheet

ARRAY — fast index access; compact storage; middle insertion/deletion often shifts elements. LINKED LIST — linked nodes; useful local insertion/deletion; slow random access. STACK — LIFO; push/pop; undo, recursion, nested structures. QUEUE — FIFO; enqueue/dequeue; waiting systems and BFS. HASH TABLE — key/value lookup; expected O(1) under typical assumptions; collisions matter. TREE — hierarchy; parent/child relationships. BST — ordered binary tree; balanced search near O(log n), skew can reach O(n). HEAP — priority-focused; min/max at root; priority queues and top-k patterns. Selection checklist: 1. What operation dominates? 2. Do I need index, key, FIFO, LIFO or priority access? 3. Do I need ordering or uniqueness? 4. What are memory and performance constraints? 5. What are the practical and worst-case behaviors?

Summary Notes

  • There is no universally “best” data structure.
  • Big-O describes growth, while constants and hardware affect practical performance.
  • Specialized structures exist because workloads differ.
  • Problem-pattern recognition is more valuable than isolated memorization.
