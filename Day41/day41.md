Key Learnings

A data structure should be selected based on the operations and constraints of the problem.

Arrays provide efficient indexed access, while linked lists can make local insertion/deletion convenient when the position is known.

Stacks model LIFO behavior and are useful for undo systems, recursion and nested structures.

Queues model FIFO behavior and are useful for waiting lines and breadth-first processing.

Hash tables provide expected fast key-based lookup under typical assumptions, while collisions can affect performance.

BSTs use ordering to support search, but an unbalanced BST can degrade toward linear behavior.

Heaps are optimized for priority access rather than keeping all elements completely sorted.

Big-O is important, but practical performance also depends on constants, memory locality and hardware.

Final Reflection

The main insight from the project is that data structures are not simply “better” or “worse.” Their usefulness depends on what a program needs to do repeatedly. Recognizing the dominant operation and matching it to the right structure is a core problem-solving skill.
