# 30-Day Growth Plan — Defend Your Experience

Goal: continue improving the existing **Vanilla HTML/CSS/JavaScript + Local Storage + Anthropic AI runtime** product without a framework rewrite or unnecessary scope expansion.

## One milestone per day

1. Record the v1.0 baseline and known limitations.
2. Clean repository paths and naming.
3. Finalize README and setup instructions.
4. Run the complete acceptance flow.
5. Audit empty, file, AI and storage error states.
6. Audit interview UX.
7. Improve claim extraction quality.
8. Improve evidence-gap presentation.
9. Test adaptive questioning with varied answers.
10. Refine interviewer prompting without changing the core rules.
11. Audit all eight evaluation dimensions.
12. Improve Defense Report readability.
13. Improve repeated-session comparison.
14. Verify report and JSON exports.
15. Test refresh, reopen, reset and duplicate-save behavior.
16. Run a responsive desktop/tablet/mobile pass.
17. Run an accessibility and keyboard pass.
18. Verify the actual deployment/runtime authentication path.
19. Check large-input and long-session behavior.
20. Create a realistic demo dataset.
21. Rehearse the complete live demo.
22. Write a portfolio case study.
23. Add factual project bullets to the resume.
24. Practice architecture and product interview explanations.
25. Write a technical request-lifecycle note.
26. Prototype one small improvement that strengthens claim defense.
27. Run a real student usability session.
28. Triage feedback into bugs, UX improvements and future scope.
29. Prepare a release candidate and avoid scope creep.
30. Create the next documented version milestone and record what changed.

## Rules

- Do not add an API key to browser source.
- Do not weaken the source-of-truth principle.
- Do not let future features replace the core claim-defense loop.
- Measure usability and evidence quality, not only feature count.
- Keep the core flow testable end to end.
